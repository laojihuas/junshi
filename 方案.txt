## 项目提示词方案：军师-恋爱指导工具（网页版）

### 一、项目概述

开发一个基于 IMA 知识库的“微信聊天指导工具”网页应用（H5）。用户可在此工具中手动创建代表不同微信好友的聊天窗口，将对方的话粘贴进去，由 IMA 知识库生成回复建议，用户复制后去微信回复对方。

**核心商业模式**：50 次免费试用，之后按月付费 88 元/月，通过发卡平台实现自动化付费闭环。

**技术架构**：前端（HTML/CSS/JS）托管于帽子云，后端数据与用户管理使用 Supabase，代码版本管理使用 GitHub/Gitee。

---

### 二、核心功能需求

#### 2.1 用户系统（Supabase 实现）

- **用户注册/登录**：支持手机号或邮箱注册登录。
- **用户状态字段**：
  - `usage_count`：已使用次数（试用期计数）
  - `is_vip`：是否为付费会员（布尔值）
  - `vip_expires_at`：会员到期时间（时间戳）
  - `device_id`：设备唯一标识（用于防共用）
  - `activated_at`：首次激活时间

#### 2.2 主界面：仿微信聊天列表

- **好友列表页**（类似微信首页）：
  - 显示所有已创建的“好友”条目（头像可用默认图标 + 好友昵称+备注）
  - 每个好友条目显示最新一条消息预览和时间
  - 底部有“新建好友”按钮
- **新建好友**：
  - 弹出输入框，让用户输入“好友昵称”
  - 创建后自动生成一个独立的对话窗口

#### 2.3 聊天对话窗口

- 打开某个好友后，进入对话界面（类似微信聊天页）
- **输入区**：一个文本框，用户粘贴微信聊天中对方的原话
 **粘贴按钮**：点击后将剪贴板内容粘贴
- **发送按钮**：点击后将文本发送给 IMA API
- **回复展示区**：IMA 返回的回复建议显示在聊天界面中（模拟对方回复样式）
- **复制功能**：每条 IMA 回复旁有一个“复制”按钮，点击一键复制回复内容
- **对话历史**：所有来往消息保存在 Supabase 中，切换好友后保留

#### 2.4 IMA API 调用

- **接口**：`b61f6470607e5bde93800ea05fc67dff` 或具体 OpenAPI 端点
- **调用方式**：将用户输入的文本作为 `query` 参数，`knowledge_base_id` 为你创建的 IMA 知识库 ID
- **鉴权**：使用你的 `Client ID` 和 `API Key`（注意：API Key 只能放在后端调用，不可暴露在前端）
- **实际做法**：前端将用户输入发送到 Supabase Edge Function 或你自己的后端服务，由后端携带 API Key 去调用 IMA，再将结果返回前端

#### 2.5 使用计数与付费墙

- **计数逻辑**：
  - 每次用户成功调用 IMA API（即成功获得回复），`usage_count` 加 1
  - 仅对非 VIP 用户计数，VIP 用户不限制
- **付费墙触发**：
  - 当 `usage_count >= 50` 且 `is_vip = false` 时，任何调用 IMA 的请求都被拦截
  - 页面弹出付费引导弹窗，提示“免费试用已结束，按月购买 88 元/月”
- **弹窗内容**：
  - 显示购买说明
  - 一个输入框：“请输入激活码”
  - 一个“激活”按钮
  - 一个“如何获取激活码？”的指引链接或文字

### 三、付费闭环设计（发卡平台方案）

#### 3.1 发卡平台接入

- **选择平台**：从链动小铺入驻
- **商品设置**：
  - 商品名称：“军师 聊天指导工具 - 月度会员”
  - 价格：99 元
  - 卡密类型：生成一批唯一的一次性激活码（长度建议 16-20 位，含字母数字）
- **自动化流程**：
  1. 用户点击付费弹窗中的“购买”按钮，跳转到发卡平台商品页
  2. 用户扫码支付后，平台自动发送激活码给用户
  3. 用户复制激活码，回到你的网页工具，在弹窗输入框中粘贴并点击“激活”
  4. 前端调用 Supabase API 验证激活码有效且未使用
  5. 验证通过后，将用户 `is_vip` 设为 `true`，`vip_expires_at` 设为当前时间 + 30 天，该激活码标记为已使用

#### 3.2 激活码管理（Supabase 表）

- 创建 `activation_codes` 表，字段：
  - `code`：激活码字符串（唯一索引）
  - `used`：是否已使用（布尔值）
  - `used_by`：使用该码的用户 ID
  - `used_at`：使用时间
  - `created_at`：生成时间

#### 3.3 防共用机制

- **设备绑定**：
  - 用户注册/首次登录时，前端通过 JS 采集设备指纹（可使用 FingerprintJS 库）
  - 将设备指纹存入 Supabase 用户表的 `device_id` 字段
  - 每次登录时校验当前设备指纹与存储的是否一致，若不一致则提示“此账号已在其他设备登录，请重新验证”
- **激活码一次性**：每个激活码只能成功激活一次，激活后立即标记已使用

### 四、技术实现要点

#### 4.1 前端（帽子云托管）

- 纯静态页面，使用 HTML + CSS + JavaScript
- CSS 框架可选：Tailwind CSS 或原生 CSS，模仿微信聊天风格（绿白配色）
- 使用 Supabase JS SDK 进行数据操作和用户认证
- 界面适配移动端（响应式设计），因为用户主要在手机上使用

#### 4.2 后端逻辑（Supabase Edge Functions）

- 创建 Edge Function 处理 IMA API 调用，避免前端暴露 API Key
- 在 Function 中判断用户是否可调用（次数或 VIP 状态）
- 在 Function 中记录使用次数

#### 4.3 数据表结构（Supabase）

**users 表（由 Supabase Auth 自动生成，扩展以下字段）：**

| 字段名 | 类型 | 说明 |
|--------|------|------|
| usage_count | integer | 默认 0 |
| is_vip | boolean | 默认 false |
| vip_expires_at | timestamp | 可为空 |
| device_id | text | 设备指纹 |
| created_at | timestamp | 注册时间 |

**chat_sessions 表：**

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | uuid | 主键 |
| user_id | uuid | 关联 users |
| friend_name | text | 好友昵称 |
| created_at | timestamp | 创建时间 |
| updated_at | timestamp | 最后更新时间 |

**chat_messages 表：**

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | uuid | 主键 |
| session_id | uuid | 关联 chat_sessions |
| role | text | 'user' 或 'assistant' |
| content | text | 消息内容 |
| created_at | timestamp | 发送时间 |

**activation_codes 表：**

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | uuid | 主键 |
| code | text | 唯一激活码 |
| used | boolean | 默认 false |
| used_by | uuid | 使用用户 ID |
| used_at | timestamp | 使用时间 |
| created_at | timestamp | 生成时间 |

#### 4.4 IMA API 调用流程

```
用户输入 → 前端 → Supabase Edge Function 
  → 校验用户状态（次数/VIP） 
  → 携带 API Key 调用 IMA 
  → 返回结果 → 前端展示并增加计数
```

### 七、注意事项与风险提示

1. **API Key 安全**：绝对不能把 IMA 的 API Key 写在前端代码中，必须通过 Supabase Edge Function 或自建后端代理调用。
2. **发卡平台风险**：发卡平台本身是灰色地带，建议定期提现，不要沉淀大额资金；如有条件，长期应注册个体户接入正规支付。
3. **数据备份**：Supabase 有免费额度限制，建议定期导出用户数据备份。
4. **用户体验**：付费弹窗要设计得友好，不要让用户反感；
5. **合规声明**：在页面底部添加“本工具仅为辅助建议，不代表专业意见”等免责声明。
