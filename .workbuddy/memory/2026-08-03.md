## IMA 整句检索实测(为混合检索设计做验证)

**背景**:用户想做混合检索(语义检索 + 整句检索,语义优先)。先实测 IMA `search_knowledge` 对整句的支持。

**实测方法**:直接 POST `https://ima.qq.com/openapi/wiki/v1/search_knowledge`,headers 用 `ima-openapi-clientid` + `ima-openapi-apikey`(凭证 ~/.config/ima/),body `{query, cursor:'', knowledge_base_id:nIUQTuLN18QIpfhpUKzd1iziyTgw0-Bj81KAUl31VFI=}`。返回层级是 `data.data.info_list`(不是 data.info_list)。

**实测结论(三组,重要)**:
1. **真整句不可行**:≥6 字 query 全部返回空(6/8/10/12/14/19 字场景全 0 命中);带 history/system_prompt 透传也救不了(IMA 后端不做整句语义搜索)
2. **2-4 字短语完全有效**:怎么回(3字)=47 命中、怎么安慰(4字)=3、忽冷忽热(4字)=5、怎么哄她(4字)=2、不回(2字)=25
3. **"4字0命中"是文档词覆盖问题,不是长度问题**:被骂/难受/被领导骂/想要见面 都 0 命中(知识库无此类文档),而同长度"怎么安慰/忽冷忽热"命中正常

**对混合检索设计的推论**:IMA 整句路只能退化为"LLM 从整句压缩 2-4 字核心短语(不限词表)"——与现有 bigram 字面切词互补(bigram 切"领导/难受"这类库外词,LLM 压缩能产出"怎么安慰"这类库内高频短语)。真整句匹配只剩本地全文缓存表 + 整句相似度一途。

**测试脚本**:`.workbuddy/tmp/ima_sentence_test*.mjs`(临时,不提交 git)
