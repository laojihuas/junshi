## v51 字数压缩 A+B+C(11:05,✅ version 51 已上线)

**背景**:用户反馈军师输出"字数比效多"。诊断出三个放大器:
1. 推拉结构三步指令(先回应→调侃→钩子)逼模型分句输出 → 最大元凶
2. "1-2 句"只管句数不管字数(中文一句可 40+ 字)
3. thinking=max + max_tokens=3000 给了长输出空间;后台"5-25 字"是软表述且被长 system 淹没

**实施(A+B+C 纯提示词,不动参数/架构)**:
- A 硬字数:【自洽与输出要求】"输出 1-2 句" → "整条 ≤30 字,通常 1 句 ≤20 字,最多 2 句合计 ≤30 字;超过=失败必须压缩重写"
- B 推拉压进一句:【语气与态度】推拉结构改为"三步用措辞在同一句完成(回应+调侃+钩子),严禁分句输出;每轮只发 1 句宁缺毋滥"
- C 示例驱动:追加 3 个 ≤20 字范例(含字数标注)

**验证(deploy_v51.mjs,8 场景全绿)**:≤30 字 8/8,平均 20 字;长消息用例(对方 60 字)回复 27 字,"我短她长"执行到位;人味保留(攻击反击/调情/否定/低落共情/挽回期稳住全部达标,attack_detected 逻辑正常)

**注意**:v14 测试输出其实平均 15-25 字已不短,但用户实际使用(带记忆卡/套路/知识库上下文更长)时偏长;v51 的"超过=失败必须重写"硬约束+示例是主要收效手段。后续若仍超标 → D(max_tokens 3000→1200)+ E(长度兜底重试)。
