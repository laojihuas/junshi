## 手机左边缘右滑返回修复（已部署 commit 7953a49）

- **问题**：聊天页左边缘右滑（系统手势=浏览器后退）直接退出浏览器，而非返回好友列表；应用是纯 SPA，`App.navigate()` 只切 CSS class，从不写 history
- **方案**：History API 接管系统手势
  - `js/chat.js` `open()`：进入聊天时 `history.pushState({page:'chat',friendId},'')`；新增第三参 `fromHistory=true`（popstate 前进/恢复触发）不 push 避免栈膨胀
  - `js/chat.js` `back()`：`history.state.page==='chat'` 时走 `history.back()`，否则直接 fallback 切好友列表（防死循环）
  - `js/app.js` `_bindEvents()`：监听 `popstate` —— 后退（state 非 chat）→ `Chat.back()` 回好友列表；前进（state 是 chat）→ `Chat.open(friendId,false,true)` 恢复会话
- 效果：右滑手势、顶部返回键、页面返回按钮三路统一；好友列表页右滑退出浏览器属系统行为无法拦截（可接受）

## ima-proxy v17：套路执行机制（strategy，已云端部署 ACTIVE，version 17）

- **需求背景**：用户澄清 junshi 定位 = 军师**扮演用户与女生对话**，输出以话术为主、分析基本不用；「恋爱教学 20M」不舍得删，希望其中惯例/魔术/理论**武装到多轮聊天布局**：检索到某个惯例后，后续每一轮话术都延续该布局贯彻技巧；且每轮新检索不得带偏方向；"/"开头文字 = 用户指令可打断
- **实施**（`supabase/functions/ima-proxy/index.ts`）：
  - `MemoryCard` 新增 `strategy` 字段（`StrategyState`：name/goal/steps[2-6]/rounds_used/max_rounds/stated_at）
  - `extractStrategy()`：检索结果含惯例特征词（惯例|魔术|玩法|套路|步骤|操作|流程|布局|开场|进阶|收尾|推拉|框架|冷读）→ LLM 提炼 `{name,goal,steps}` 启动套路；steps<2 或未命中特征则不启动（静默普通回答）
  - `buildSystemContent` 注入【当前执行套路】：**套路=方向盘（优先级高于检索参考资料），检索=弹药（方向一致采用/冲突忽略或借鉴语气）**；先顺应女方反应再拉回套路方向；**严禁向对方提及套路/步骤/进度等元信息**，输出必须是可直接发送的自然消息；套路完成/失效自然收尾
  - `"/"` 开头输入 → `strategyClear` 清除执行中套路（与统一提示词中"用户指令"规则呼应）
  - `updateMemoryCard` 每轮 `rounds_used+1`，达 `max_rounds`（=steps×2，至少 6）自动终止
  - `_debug` 新增 `strategy_name/strategy_rounds/strategy_clear`
- **部署坑**：本机 curl **schannel SSL 握手失败**（`curl: (35) failed to receive handshake`，重试/`--ssl-no-revoke` 均无效）→ 改用 **Python requests**（venv 已装 requests）multipart 部署成功（HTTP 201）；临时脚本放 Temp 已清理
- **冒烟测试**：假 JWT 返回 `UNAUTHORIZED_INVALID_JWT_FORMAT`（函数在线、进入认证环节）
- **待验证**：真实用户登录连续对话 → 看 `_debug.strategy_name` 是否出现、多轮是否延续布局、"/"指令能否打断、检索到冲突惯例是否不跑偏
