## prompt-update 校验 bug 修复（commit fb6de24，version 11）

**用户反馈**：admin 后台保存 LLM 参数报"保存失败：temperature 必须为 0 / 2 之一"
**根因**：v10 改 LLM_PARAM_RANGE 为 `Record<string, [number,number] | string[]>` 后，用 `Array.isArray(range)` 区分枚举/区间——但**数值区间 `[0,2]` 本身也是数组**，误走枚举分支（`[0,2].includes(0.4)`=false）→ 报错
**修复**：改用**首元素类型**区分（`typeof range[0]==='string'` → 枚举校验；否则数值区间校验）
**教训**：改校验逻辑必须端到端测保存路径（上轮漏测才暴露）
**端到端验证**（测试管理员建号→is_admin=true→登录→保存验证→恢复原值→清理）：
- 合法值（含 thinking_mode）→ 200 success ✅
- temperature=9 → 400 "temperature 必须为 0~2 之间的数字" ✅
- thinking_mode='extreme' → 400 "thinking_mode 必须为 off / low / high / max 之一" ✅
- 原值恢复（用户当前线上配置：temp 1 / fp 0.5 / pp 0 / max_tokens 5000）
