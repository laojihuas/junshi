## Token 消耗真实测量与分析（ima-proxy v14）

**背景**：用户反馈 token 消耗大。用真实 DeepSeek API + IMA 知识库复刻完整调用链，逐环节采集 usage。

**实测数据（典型场景：暧昧期·10轮历史·对方心情低落，单次请求 9,602 tokens）**：
- 定向摘要 summarizeRef ×4 = 4,253（44.3%，**最大头**，每次输入≤3500字）
- 主回复 = 2,425（25.2%，system 3416-4196 字，其中知识库参考占 73%）
- 套路提炼 extractStrategy = 1,790（18.6%，仅套路启动轮触发，摊薄低）
- 语义拆解 517 / 画像提取 375 / 整句压缩 242

**关键实测结论**：
1. **DeepSeek 前缀缓存命中率仅 10%**：system 组装顺序中"对方近期话/自己发过话"（每轮变化）位置太靠前，前缀在第 ~256 token 处被打断，后 90% 每轮全价重算。且这两块与 llmHistory（最近10条全文）**完全重复**，属纯冗余注入（仅窗口恢复场景需要）。
2. **同话题连续轮次检索 100% 重合**（轮1 vs 轮2 共 7/7 条），话题切换才全变 → 文档内容缓存（media_id→摘要，TTL 1h）可消灭重复 summarizeRef+全文拉取。
3. 中文在 deepseek-v4-flash 下约 1 字 ≈ 0.6-0.65 token（实测反推）。

**优化方案（P0 三项）**：
- P0-1 文档内容缓存（fetchItemsContent 处，Map/kb_docs，TTL 1h）：同话题轮省 ~4000 tokens
- P0-2 summarizeRef 截断 3500→1800 字：省 ~1500-2000/请求
- P0-3 主回复 system 重排（固定块前移→缓存命中 10%→40%+）+ 去冗余（llmHistory≥4 条时不注入近期话/自己话，仅 llmHistory 为空时兜底）：省 ~500-800 tokens + 缓存折扣
- 预期：首轮 -26%，同话题连续轮 -49%
- 提醒：thinking_mode 若从 off 调高，成本 2-5 倍

**测试脚本**：`%TEMP%/junshi_token_measure/`（measure.mjs 单次链路 / cache_test.mjs 缓存命中 / overlap_test.mjs 检索重合度）；报告 token_report.html。凭证用环境变量 DEEPSEEK_API_KEY + ~/.config/ima/，未落库。

## IMA 向量检索切块机制探查（实测确认）

**用户问题**：IMA 是否对大文章切块、检索时只返回小块而不是全文（省 token）？

**实测结论（2026-08-04，用 ~/.config/ima/ 凭证直连 ima.qq.com）**：
1. **`search_knowledge` 不返回任何正文**：只返回 `media_id/title/parent_folder_id/highlight_content/media_type`，且 `highlight_content` 恒为空（试了标题精确词、正文词、短词，全部 0 字符）→ IMA 检索 API 是"条目级"命中，不是"片段级"。
2. **`limit` 参数不生效**：传 limit=3 仍返回 100 条；无 is_end/next_cursor（游标分页字段缺失，但调用不报错）。
3. **全文只能整篇下载**：`get_media_info` → `url_info.url`（COS 直链）→ fetch 拿全文。实测文档 2K~13K 字符不等（md 类型 media_type=7）。**IMA 内部虽向量化切块，但 OpenAPI 不暴露切块返回能力**。
4. **对 ima-proxy 的影响**：现有链路 = 检索（免费、无正文）→ 下载全文 → 截断 500 字或定向摘要（≤3500 字喂 LLM）。token 大头在 summarizeRef 输入，不在检索本身 → 印证 P0-2（3500→1800）与 P0-1（文档内容缓存）方向正确。
5. 后续优化可考虑：既然 highlight_content 恒空，别指望 IMA 返回片段；要继续省 token 只能靠缓存摘要 + 缩短摘要输入。

**清洗噪音清单（话术库特有）**：
- frontmatter / `# XX话术部落完整合集` 主标题 / `## 第X页` 分页标记
- `description:` 网页描述 / `> 热搜` / `> 来源`
- 尾部 `- [第 X 页](http...)` 分页链接列表（CRLF 换行，注意 `## 原文链接` 是双井号）
- 纯分隔线 `---`/`***`（源文件有 CRLF `^M`，node 读入后 trim 处理）

**踩坑**：文件是 CRLF 换行 + 尾部常见 `## 原文链接`（双井号）——单井号正则匹配不到，需 `^#{1,6}`。
